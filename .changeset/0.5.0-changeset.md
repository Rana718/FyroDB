# FyroDB 0.5.0 Release Notes

### Distributed Cluster & Replication
- **Resilient Cluster Failover**: Hardened node state machine transitions, epoch increment coordination, and dynamic topology routing tables under network partitions.
- **Formal Verification of Slot Ranges**: Added SMT machine-checked proofs in Verus (`proofs/verus/slot_ranges.rs`) proving slot boundary completeness and non-overlapping range invariants across all 16,384 hash slots.
- **Multi-Node Cluster E2E Harness**: Added Python multi-node cluster E2E integration test suite (`tests/e2e/python/cluster_e2e.py`) and cluster Go benchmarks (`bench/cluster.go`).
- **Mutation Log & Streaming Replication**: Overhauled the replication log with 64-bit monotonic offsets, atomic snapshot handoffs, and real-time lag tracking.

### Persistence & Data Integrity
- **AOF Multi-Writer Window Ordering**: Fixed sequence number assignment and window refill races across concurrent worker threads, verified by formal models in `proofs/verus/aof_sequence.rs`.
- **RDB Corruption Defenses**: Hardened snapshot restore routines to validate RDB header magic, slot mappings, and CRC checksums before committing table state.
- **Quiescent Write Fence**: Enhanced write ticket barriers (`WriteFence`) to guarantee total keyspace quiescence during snapshot creation and slot migrations.

### High-Throughput I/O & Networking
- **Configurable `io_uring`**: Added runtime opt-in `io_uring` batched socket transmission via Docker Compose (`FYRODB_IO_URING=1`) with transparent, zero-overhead fallback to `send(2)`.
- **Edge-Triggered Connection Ingress**: Optimized ingress buffers and pre-allocated command scratch structures for edge-triggered mio polling.

### Data Structures & Memory Optimization
- **QuickList Allocation Right-Sizing**: Tuned slotted chunk pre-allocation to eliminate heap allocations during queueing bursts.
- **Sorted Set Vector Optimization**: Refined chunked vector balancing in `ZSetData` and streamlined 64-bit member Bloom filter bit checking.
- **CompactKey Binary Safety**: Hardened 64-bit unaligned word copies for arbitrary binary keys without allocations.

### CI/CD Intelligence & Release Workflows
- **Intelligent CI Routing**: Optimized GitHub Actions workflows so full suites run on PR open, fast checks (`test`, `lint`, `verus`) run on every push, and heavy Docker E2E and benchmarks execute on dedicated labels (`test-case`, `e2e-testcase`, `benchmark-validation`).
- **Automated PR Labeling**: Integrated `actions/labeler@v5` to tag PRs automatically based on changed files.
- **Automated Versioned Changeset Releases**: Integrated tag-triggered GitHub Release workflow reading scoped notes directly from `.changeset/<version>-changeset.md`.
