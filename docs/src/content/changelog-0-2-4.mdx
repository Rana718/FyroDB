# v0.2.4

Released: October 2026

v0.2.4 introduces major low-level architectural optimizations across the core key-value engine, network pipelining, and parsing layers. Pipelined GET achieves an all-time peak throughput record of **53.38M ops/sec** (187ms for 10M keys), Mixed SET/GET drops to **44ms** (45.87M ops/sec), and Hot Key contention latency drops by over **2.4×** to **265ms** (37.68M ops/sec).

---

## Highlights

- **Pipelined GET Breakthrough (53.38M ops/sec)**:
  - **187ms** for 10 million GET operations under loopback TCP with 100 concurrent clients.
  - Zero-copy cache hit path in `dispatch_get_run`: `CompactKey::eq_bytes` validates raw bytes directly on prefetched `Entry` pointers, completely bypassing `std::str::from_utf8` validation and function dispatch layers on cache hits.
  - RESP bulk format strings are synthesized directly into connection output write buffers.

- **In-Place Atomic CAS SET Updates (39.62M ops/sec)**:
  - Pipelined SET achieves **39.62M ops/sec** (252ms for 10 million operations).
  - In-place mutation via `SmallStr::overwrite_bytes` under per-key spinlock with sequence bumping and release ordering, eliminating heap allocations and string clones on update paths.

- **Hot Key Contention Slashed by 2.4× (37.68M ops/sec)**:
  - Single-key contention latency plummeted from 647ms down to **265ms** (over **2.4× faster**) for 10 million operations on a single contended key across 100 concurrent clients.
  - Direct atomic CAS in-place updates eliminate contention bottlenecks on hot entries.

- **Mixed SET/GET Sub-45ms (45.87M ops/sec)**:
  - Mixed SET/GET (50/50) execution time dropped from 69ms to **44ms** (45.87M ops/sec).
  - Redundant prefetch bypass in `prefetch_ahead`: detects incoming pipelined GET (`*2\r\n$3\r\nGET`) and SET (`*3\r\n$3\r\nSET`) runs and yields directly to specialized run engines, eliminating 32 duplicate hash calculations and slot probes per pipeline batch.

- **Sub-100ms Latency Across Complex Workloads**:
  - **Pub/Sub delivery**: **88ms** elapsed, **113.98M msg/sec** fan-out throughput.
  - **Pub/Sub publish**: **87ms** elapsed, **2.29M ops/sec**.
  - **INCR (atomic counters)**: **18ms** elapsed, **108.56M ops/sec**.
  - **LPUSH/RPOP (queue)**: **30ms** elapsed, **66.93M ops/sec**.
  - **HSET/HGET (sessions)**: **45ms** elapsed, **44.44M ops/sec**.
  - **SADD (sets)**: **50ms** elapsed, **40.38M ops/sec**.
  - **JSON.GET (documents)**: **76ms** elapsed, **26.21M ops/sec**.
  - **XADD (streams)**: **84ms** elapsed, **23.76M ops/sec** via `WriteOp::Xadd` and `Store::xadd_batch` varint streaming.

- **Wire Parser Branch Reduction**:
  - Replaced split 32-bit and 16-bit comparisons in `try_fast_get_at`, `try_fast_get_key_at`, `try_fast_set_at`, and `try_fast_set_key_val_at` with single unaligned 64-bit word reads (`u64::from_ne_bytes`), reducing branch count across all fast-path parsers.

- **Geospatial & Sorted Set Enhancements**:
  - Replaced 52-step division loop in `src/storage/geo.rs` with 5-instruction Morton bit-interleaving (`spread26`), dropping `GEOADD/GEODIST` elapsed time under 199ms.
  - Direct output buffer writing in `zadd_added_flags_into` and right-append optimization in `ZSetData::place` with `CHUNK_MAX = 64`.

- **Strict Memory Safety**:
  - Maintained 24-byte `SmallStr` footprint and 64-byte `Entry` size in `mimalloc`.
  - Peak RSS is **876.28 MB**, strictly under the 900MB memory ceiling.
  - Zero clippy warnings under `cargo clippy --workspace -- -D warnings`.
