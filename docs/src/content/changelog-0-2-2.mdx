# v0.2.2

Released: October 2026

v0.2.2 ships the **vector search and AI engine** (HNSW, FLAT, BM25 full-text, `FT.HYBRID` RRF/LINEAR fusion) alongside a round of memory and throughput optimizations: arena milestone-shrink, two-pass FLAT Int8 pre-filter, lock-free search pool dispatch, O(bytes) bitmap operations, zero-copy cursor reads, and O(output) complement filters. Zero clippy warnings across all crates.

Against a 12-node Redis Cluster, a single FyroDB node delivers **9.14M Pipeline-64 SET**, **47.12M INCR**, **46.69M Hot Key**, **70.44M Pub/Sub msg/sec**, **5.0K HNSW KNN-10 q/s** (4.55×), and **42.6K text-term q/s** (26.6×).

---

## Highlights

- **Vector Search (HNSW + FLAT)**: `FT.CREATE`, `FT.SEARCH` KNN, `VECTOR_RANGE`, tag/numeric/text pre-filters, `QUANTIZATION INT8 | RABITQ | NONE`, exact rerank from the stored hash field, persistence in RDB v3, incremental maintenance via a write hook.
- **BM25 Full-Text**: Unicode tokenizer, RediSearch stopwords, BM25 (k1 = 1.2, b = 0.75) ranking, `FT.AGGREGATE` GROUPBY/REDUCE with cursors.
- **FT.HYBRID**: Lexical and vector legs run in parallel on the pool and fuse with RRF (Cormack) or LINEAR weighting.
- **HNSW Arena Milestone-Shrink**: Arena buffers shrink at each power-of-two node count milestone (`last_shrink: AtomicUsize`), reducing cache-miss pressure on streaming HSET inserts as well as bulk builds.
- **Thread-Local Scratch Zero-Alloc**: `Scratch` gains `q_int8`, `acorn_hop`, and `acorn_frontier` — ACORN traversal and FLAT two-pass scans share pre-allocated working memory with zero hot-path allocation after warmup.
- **Two-Pass FLAT Scan**: Int8 pre-filter pass narrows candidates before exact f32 rerank; codes are held in thread-local scratch to avoid per-query allocation.
- **Lock-Free Search Pool**: Job dispatch uses `crossbeam::SegQueue<Job>` per priority tier; submission never takes a lock. Index builds run on the low-priority tier so queries stay responsive during background work.
- **`prepare_batch` Burst HSET**: N consecutive HSET writes on the same vector field take one write-lock instead of N, cutting ingestion lock overhead.
- **`cursor_read` Zero-Clone**: `FT.CURSOR READ` uses `Vec::split_off` instead of a full cursor-row clone, eliminating O(n²) work per page.
- **`complement_ids` Sorted-Merge**: Negated filter sets resolve as an O(output) sorted merge over the ascending id range instead of a 100 KB boolean array per query.
- **ZSet No-Alloc Update**: `ZSetData::insert` probes the member index before allocating a `SmallStr`, skipping all allocation on score-update paths.
- **O(bytes) Bitmap Ops**: `BITCOUNT` and `BITPOS` operate at the byte level using hardware `count_ones()` / `leading_zeros()` instead of per-bit loops.
- **Zero Clippy Warnings**: All 16 warning categories resolved across `fyro-vector`, `customhash`, `rust-zmalloc`, and `src/`.
